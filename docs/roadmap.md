# 로드맵

이 문서는 아직 완료되지 않은 작업만 관리한다. 구현을 마친 항목은 제거하고,
현재 동작 설명이 필요하면 [아키텍처](./architecture.md)로 옮긴다.

## P0: 실제 정보 사용 전

- 운영 저장소와 백업의 암호화·보유·삭제 기준을 정한다.
- AI 요청과 로그에서 대상자 식별정보가 분리되는지 검증한다.
- 생성 프롬프트에서 입력에 없는 사실을 보충하도록 하는 지시를 제거한다.
- 생성 결과의 모든 주장에 입력 근거가 있는지 검증하는 단계를 추가한다.

완료 조건: 실제 개인정보를 넣기 전에 접근 통제, 데이터 취급 기준, 사실성
검증이 코드와 운영 절차에 반영되어야 한다.

## P0.5: 배포 및 작업 복구 검증

- 합성 데이터로 실제 Turso 연결, Google OAuth, Gemini 일반 응답·스트림을 검증한다.
- 기존 Ollama 어댑터에도 정상 종료·중간 오류·잘림 검증과 HTTP 오류 본문 제외를 적용한다.
- Vercel Hobby 사용 목적 적합성과 계정 연결을 확인한 뒤 Preview를 검증한다.
- 주간 작업의 오래된 PROCESSING 복구와 동시 중복 요청 방지를 구현한다.
- 운영 전환 시 DB 백업·복원과 수동 Docker 복구 경로를 검증한다.

## P0.5: 로컬 DB 다중 연결 가용성

- 현재 libSQL 파일 드라이버는 두 연결이 동시에 쓰다가 BEGIN에서 잠금 실패한 연결을
  재사용하면, 제한된 재시도 후에도 COMMIT의 SQLITE_BUSY가 남는 경우가 있다.
  요청 실패 시 공간/구성원의 중복 생성은 방지하지만 모든 요청의 성공을 보장하지 않는다.
  드라이버의 안전한 연결 복구나 수정 버전을 검증해야 하며, 진행 중 조회가 있는 연결을
  임의 재연결하지 않는다. 단일 인스턴스 동시 쓰기 검증과 원격 libSQL 검증을 구분한다.

## P0.5: 기관 확장과 운영 적용

- 기존 자료의 workspace/관리자 배정은 별도 승인 후 수행한다. 실제 DB migration과 로그인한 두 계정의 공유·철회 E2E 검증은 아직 남아 있다.
- 현재 개인/기관 공통 workspace 경계 위에 필요할 때 추가 공간 생성·선택, 기관 구성원 관리·초대 UI를 구현한다. 구성원 추가로 자료를 자동 공개하지 않는다.
- 작업별 권한의 감사 기록, 공유 관리자 이전·계정 삭제 시 처리 정책을 정한다.
- 월 비용 한도는 별도로 결정하고 공급자 측 지출 제어와 운영 알림을 검증한다. 앱의 일일 호출 횟수 제한은 두지 않는다.
- 기관 위치·시간대 옵션은 같은 시간 기준 경계를 확장한다. 현재 Asia/Seoul 고정이다.
- 복잡한 역할 관리, 기관 결제·통계는 필요성이 확인된 뒤 구현한다.

## P1: 기록 신뢰성

- 원문 관찰 메모와 생성 결과의 근거 연결을 저장한다.
- 생성 결과를 초안/검토/확정 상태로 구분한다.
- 인지·행동 분류를 사용자가 수정할 수 있게 한다.
- 주간 기록은 확정된 관찰 사실을 근거로 생성한다.
- 근거 부족, 금지 표현, 날짜·대상자 혼동을 검사한다.
- 검증 실패 시 보수적 재생성 또는 비 AI 템플릿으로 대체한다.

완료 조건: 문장 단위로 근거를 확인할 수 있고, 입력에 없는 사실이 최종
기록에 들어가지 않는 회귀 테스트가 있어야 한다.

## P1: 기존 UI 회귀 (클라우드 전환과 별도)

- DialogTrigger와 내부 Button의 중첩 button을 제거하고 키보드·모바일 동작을 검증한다.
- 동적 관찰 입력의 RHF 내부 field ID와 도메인 ID 혼용으로 아코디언이 열리지 않는 경우를 수정한다.

## P2: 사용성

- 사건, 관찰, 제공한 도움, 이후 반응을 짧은 단계로 입력하게 한다.
- 자주 쓰는 사건 선택지를 제공한다.
- 모호한 입력에는 자유 질문 대신 선택형 확인 질문을 최대 한 개 제시한다.
- 기록 상태를 `미작성`, `메모 있음`, `검토 필요`, `완료`로 구분한다.
- 모바일 큰 글씨와 고대비 사용성을 검증한다.
- 네트워크 장애 중 임시 입력 보존 방식을 정한다.

## P3: 품질 평가

- 식별정보를 제거한 관찰 메모와 교정 문장으로 골든 데이터셋을 만든다.
- 사실 추가, 대상자·날짜 혼동, 금지 표현, 영역 분류를 자동 평가한다.
- 모델과 프롬프트 버전을 생성 결과에 남긴다.
- 실제 사용자의 수정량과 생성 소요 시간을 측정한다.

목표 기준:

- 사실 추가 0건
- 대상자·날짜 혼동 0건
- 금지 표현 0건
- 인지·행동 분류 정확도 95% 이상

## 보류

- D1 전환은 아직 구현·검증하지 않았다. 현재 연결 경계는 로컬 SQLite/원격 libSQL용이며, 원본 Drizzle API와 드라이버별 실행 결과 타입을 유지한다. D1은 무수정 대체 대상으로 보장하지 않는다. 필요해지면 기존 SQLite 스키마·업무 쿼리를 유지할 수 있는지 검증하면서 `src/db`의 드라이버/연결 조립과 환경·마이그레이션 설정을 바꾼다. 범용 repository를 미리 추가하지 않는다.
  - Workers에서는 [Drizzle D1 드라이버와 바인딩](https://orm.drizzle.team/docs/connect-cloudflare-d1)이 필요하다. Vercel/Node를 유지한다면 [인증된 Worker API](https://developers.cloudflare.com/d1/tutorials/build-an-api-to-access-d1/) 등 별도 전송 경계가 필요하다. Drizzle Kit의 `d1-http` 설정은 앱 런타임 드라이버를 대신하지 않는다.
  - D1의 batch 트랜잭션·결과 형식, Better Auth 가입/세션 및 workspace 권한, 실제 SQL·날짜 기본값·마이그레이션을 합성 데이터로 검증한다. Workers로 앱도 이동하면 Next.js 실행 어댑터와 `after()` 생명주기도 확인한다. 현재 libSQL 테스트는 D1 호환성 증명이 아니다.
  - 현재 Better Auth Drizzle 어댑터의 영향 행 수 계산은 D1의 `meta.changes`를 읽지 않는다. D1 구현 시 `updateMany`/`deleteMany`의 반환 건수도 별도로 검증하고 필요한 호환 처리를 어댑터 경계에서 해결한다.

- 음성 받아쓰기
- PostgreSQL 전환과 기관 관리 UI
- 공식 API가 확인된 경우의 케어포 연동
- Apple Silicon 최적화를 위한 MLX-LM 비교

케어포 화면 좌표를 클릭하는 무인 자동화는 UI 변경, 오입력, 계정 보안 위험
때문에 제품의 기본 방향으로 채택하지 않는다.
