# 제품 기준

## 목표

케어포올은 요양보호사가 그날 있었던 일을 단어나 끊긴 문장으로 입력해도,
자연스럽고 따뜻하며 성의 있는 일일 신체·인지 기록과 주간 기록으로 완성하는 도구다.
작성자가 다시 살을 붙이거나 전문적인 글쓰기와 말투 다듬기에 에너지를 쓰지 않도록 한다.

핵심 가치는 자동 작성 자체가 아니라 **입력된 사실을 빠뜨리거나 과장하지
않고 검토 가능한 기록 문장으로 바꾸는 것**이다.

## 사용자

주 사용자는 IT 서비스에 익숙하지 않은 요양보호사다. 제품은 사용자가 자유로운
프롬프트 작성법을 익히도록 요구하지 않고, 예측 가능한 선택과 짧은 입력으로
결과를 만들 수 있어야 한다.

## 기록 원칙

다음 원칙은 UI, 프롬프트, 저장 로직보다 우선한다.

- 원래 상황과 결과를 유지하면서 자연스러운 돌봄 맥락·일상적인 배려 표현과 작문적 보완을 적극 허용한다.
- 투약·처치·보고 여부, 새 증상·진단, 사고, 증상 호전·악화 같은 중요한 사실을 근거 없이 만들어 확정하지 않는다.
- 생성 결과는 초안이며, 사용자가 확인하고 수정한 뒤 사용한다.
- 신체와 인지 기록을 구분하되 단순 활동을 문제 행동으로 해석하지 않는다.
- 실명 등 식별정보는 AI 요청에서 가능한 한 분리한다.
- 근거가 없는 영역은 빈칸으로 두고, 메모가 없다는 이유로 “특이사항 없음”이나 “양호함”을 쓰지 않는다.
- 주간 변화나 반복성을 말하려면 둘 이상의 근거가 있어야 한다.

## 문체

작성·초안·상세·수정·조회·복사와 AI 프롬프트는 모두 **신체 영역 → 인지 영역** 순서를 사용한다.
기존 저장 키 `behaviorContent`/`cognitionContent`는 유지하며 데이터나 열을 서로 바꾸지 않는다.

60대 요양보호사를 포함해 글쓰기가 익숙하지 않은 작성자가 투박한 사실 메모만으로
바로 옮겨 쓸 만한 돌봄 기록을 얻는 것이 목표다. 어르신 곁에서 보고 도와드린 일을
동료에게 전하듯, 쉬운 말과 자연스러운 존댓말로 차분하고 다정하게 쓴다.
작성자의 나이를 흉내 내거나 일부러 맞춤법을 틀리게 쓰지 않는다.

- 메모의 단어와 결과 문장을 일대일로 대조하는 것을 생성 원칙으로 삼지 않는다.
  생략된 문장을 풀고 자연스러운 돌봄 맥락·배려 표현을 넉넉히 보완하여 성의 있게 완성한다.
  `기다리시는 마음을 헤아리며`, `조금 더 수월하게 드실 수 있도록` 같은 표현도 상황에 맞게 사용한다.
- 짧게 줄이는 것 자체가 목표는 아니다. 충분히 전해지는 만큼 쓰되, 단순한 사실은
  자연스러운 한 문장으로 완성한다. 반복이나 상투적인 장식으로 분량을 늘리지 않는다.
- 어르신의 모습은 `~하셨습니다`, 해드린 도움은 `~드렸습니다`처럼 존댓말 완성 문장으로 쓴다.
  입력의 메모식 `~하심`·`~드림`·`~함` 종결을 결과물에 그대로 남기지 않는다.
- 신체는 생활 중 행동·신체 활동과 몸의 불편함, 인지는 기억·이해·인식·생각·감정·대화와 반응을 담는다. 말로 표현했다는 이유만으로 몸의 불편함까지 인지에 넣지 않는다.
  도움은 관련 영역에 두고 같은 장면을 중복하지 않는다.
- 원래 상황과 결과를 바꾸지 않는 범위에서 따뜻함과 자연스러움, 완성 문장의 성의를 우선한다.
  배려를 담은 표현을 실제 투약·처치·보고를 했거나 증상이 좋아졌다는 단정으로 바꾸지 않는다.
  명시적인 정정은 반영하고 불확실한 중요한 사실을 확정하지 않는다.
- 전문 용어, 추상적인 평가, 상투적인 맺음말과 반복되는 주어는 피한다.
  전문적인 평가나 과장된 상투어로 성의를 대신하지 않고 생활 속의 쉬운 말로 쓴다.
- 주간 기록은 관련된 일과 도움을 엮은 한 문단으로 쓴다. 기록이 있는 날의 범위를
  넘어 임상적 변화나 상태 유지를 단정하지 않는다.

역설계 기준은 [합성 목표 예문 7개와 주간 예문](../tests/cloud/record-writing-cases.json)이다.
이 예문은 사람이 검토할 목표 결과이며 실제 모델 출력이 아니다. 일일 출력의
`[신체]` 다음 `[인지]` 형식, 정보 없는 영역의 빈칸, 기존 저장 계약은 유지한다.
문장마다 확인시키는 UI·체크리스트·추가 질문 절차는 도입하지 않는다.
자동 테스트는 예문의 저장·파싱 호환성과 호출 경로를 확인하며, 실제 모델의 문체·
사실 충실성이 목표를 만족한다는 품질 증거를 대신하지 않는다.

## 핵심 흐름

1. 대상자를 선택한다.
2. 날짜와 관찰 메모를 입력한다.
3. 일일 신체·인지 기록 초안을 생성한다.
4. 결과를 검토하고 수정하거나 복사한다.
5. 한 주의 일일 기록이 충분하면 주간 종합 기록을 생성한다.

## 로그인과 이용 권한

모든 Google 계정으로 로그인할 수 있다. 인증된 새 사용자는 기본 workspace를 자동으로
받아 자신의 대상자와 기록을 바로 만들고 AI로 초안을 생성할 수 있다. 1인 공간과
향후 기관 공간은 같은 모델을 사용한다. 자료의 공간 소속, 작성자, 구성원 관계와
작업별 권한은 서로 구분한다.

공유는 향후 기관(workspace) 단위로 확장한다. 현재 대상자 화면에는 개별 어르신의
이메일 공유·권한 부여·해제 UI를 제공하지 않는다. 기관 구성원 관리·초대·역할 설정은
후속 작업이며, 현재 구성원 추가만으로 기존 자료가 공개되지는 않는다.
기존에 저장된 명시 권한의 읽기·편집 검사는 유지하고, 기관 공유로 전환할 때 자료 범위와
권한 전환 규칙을 별도로 정한다. UI 제거만으로 기존 자료나 권한을 변경하지 않는다.

## 날짜와 과거 기록 편집

현재 기록 날짜와 “오늘”은 한국 시간(`Asia/Seoul`)으로 고정한다. 향후 기관 위치와
시간대에 맞게 변경하는 옵션을 제공하며, 현재는 기관 설정 UI를 구현하지 않는다.
코드의 날짜 기준은 [아키텍처](./architecture.md#시간-기준)의 한곳에서 관리한다.

지난주를 포함한 과거 기록도 수정 권한이 있으면 편집할 수 있어야 한다. 작성자는
자기 기록의 수정 권한을 기본으로 부여받고, 다른 사용자도 부여된 권한에 따라
수정할 수 있다. 과거 날짜라는 이유로 수정을 막거나 작성자만 수정하도록 제한하지
않는다. 기준은 작업별 권한이며 작성자별 자료 격리를 요구하지 않는다.
작성자는 대상자 읽기 권한을 유지하는 동안 자기 기록의 수정·삭제 권한을 갖는다.
공유가 완전히 철회되면 작성자도 그 대상자의 기록에 접근할 수 없다. 편집 공유를 받은
다른 사용자도 과거 기록을 편집할 수 있다. 기존 미배정 자료는 별도 승인된 공간·권한
배정 전까지 노출하지 않는다.

## MVP 범위

포함:

- 대상자 등록과 선택
- 날짜별 관찰 메모 입력
- 일일 신체·인지 기록 생성
- 생성 결과 수정, 복사, 삭제
- 일일 기록을 이용한 주간 기록 생성
- 로컬 Ollama 연동

제외:

- 진단, 위험도 판정, 치료 또는 투약 권고
- 케어포 계정 비밀번호 저장
- 케어포 화면 무인 자동 입력
- 보호자에게 보고서 자동 발송
- 다기관 결제와 복잡한 권한 체계

현재 구현 여부와 다음 작업은 [로드맵](./roadmap.md)에서 관리한다.

## UX 원칙

- 모바일을 우선하고 주요 버튼의 터치 영역과 글자를 충분히 크게 만든다.
- 사용자가 작업 맥락을 잃지 않도록 불필요한 페이지 이동을 줄인다.
- 상태와 결과를 명확한 텍스트로 설명하고 장식보다 기록 작업에 집중한다.
- 색상은 `src/app/globals.css`에 정의된 의미 기반 토큰을 사용한다.
- 접근성이 필요한 복합 UI는 Base UI (headless primitive)를 사용한다.

## 개인정보 기준

대상자의 신체·인지 기록은 민감한 돌봄 정보로 취급한다.

- AI 요청과 로그에 불필요한 식별정보를 넣지 않는다.
- `.env`, 데이터베이스, 백업을 Git에 커밋하지 않는다.
- 운영 접속은 인증된 HTTPS 프록시 또는 사설망으로 제한한다.
- Ollama와 SQLite를 공용 인터넷에 직접 노출하지 않는다.
- 대상자와 기록의 조회·작성·수정·삭제는 Google 로그인과 별도의 이용 권한 검사를 거친다. workspace 소속과 명시 공유 범위를 벗어난 자료는 조회·수정·AI 입력에 포함하지 않는다. 운영별 설정은 [운영 가이드](./operations.md)를 따른다.
