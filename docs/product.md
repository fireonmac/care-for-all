# 제품 기준

## 목표

케어포올은 요양보호사가 그날 관찰한 사실을 짧게 입력하면 쉽고 담백한 문장의
일일 인지 기록, 일일 행동 기록, 주간 종합 기록 초안을 만드는 도구다.

핵심 가치는 자동 작성 자체가 아니라 **입력된 사실을 빠뜨리거나 과장하지
않고 검토 가능한 기록 문장으로 바꾸는 것**이다.

## 사용자

주 사용자는 IT 서비스에 익숙하지 않은 요양보호사다. 제품은 사용자가 자유로운
프롬프트 작성법을 익히도록 요구하지 않고, 예측 가능한 선택과 짧은 입력으로
결과를 만들 수 있어야 한다.

## 기록 원칙

다음 원칙은 UI, 프롬프트, 저장 로직보다 우선한다.

- 사용자가 입력하지 않은 사실, 진단, 감정, 원인, 조치를 만들지 않는다.
- 관찰 가능한 행동과 사용자가 입력한 도움·반응만 기록한다.
- 생성 결과는 초안이며, 사용자가 확인하고 수정한 뒤 사용한다.
- 인지와 행동 기록을 구분하되 단순 활동을 문제 행동으로 해석하지 않는다.
- 실명 등 식별정보는 AI 요청에서 가능한 한 분리한다.
- 근거가 없는 영역은 빈칸으로 두고, 메모가 없다는 이유로 “특이사항 없음”이나 “양호함”을 쓰지 않는다.
- 주간 변화나 반복성을 말하려면 둘 이상의 근거가 있어야 한다.

## 문체

어르신을 가까이에서 살피는 요양보호사가 하루의 돌봄을 돌아보며 남기는 기록을 목표로 한다.
직접 본 일과 해드린 일을 쉬운 말로, 담담하면서도 다정하게 정리한다.
작성자의 나이를 흉내 내거나 일부러 맞춤법을 틀리게 쓰지 않는다.

- 어르신의 모습은 `~하셨습니다`, 작성자가 한 도움은 `~드렸습니다`처럼 자연스러운 존댓말로 쓴다.
- 짧은 메모는 한 문장으로 충분하다. 사실을 빠뜨리지 않는 범위에서 간결하게 쓰고 문장 수를 맞추려고 늘리지 않는다.
- 관찰 사실을 먼저 쓰고, 입력된 경우에만 조치와 이후 반응을 쓴다. 조치는 관련 사건과 함께 둔다.
- 인지는 기억·이해·인식·말씀·감정과 반응, 행동은 생활 중 하신 행동과 신체 활동을 담는다. 같은 사실을 두 영역에 반복하지 않는다.
- 따뜻함은 입력에 있는 말씀·작은 반응·도움과 존중하는 말투에 담는다. 잘하고 못함을 평가하거나 어린아이처럼 대하는 표현은 피한다.
- 감상이나 칭찬, `정성껏` 같은 수식어를 덧붙이지 않는다. 전문 용어, 추상적인 평가, 상투적인 맺음말과 반복되는 주어를 피한다.
- 주간 기록에도 같은 문체를 적용하며, 일일 기록에 없는 변화나 반복성을 보태지 않는다.

금지 예:

- 근거 없는 진단: `치매가 심해짐`
- 원인 단정: `관심을 받기 위해`
- 가치 판단: `말을 안 들음`
- 입력하지 않은 조치: `정서적 지지를 제공함`
- 근거 없는 변화: `인지 기능이 악화됨`
- 입력하지 않은 결과: 조치만 적었는데 `이후 안정을 되찾으셨습니다`

목표 문장 예시(합성 메모이며, 실제 모델의 검증 결과는 아님):

- 입력: 사건 `딸이 언제 오는지 세 번 물으심`, 감정 `걱정된다고 하심`, 조치 `점심 후에 온다고 말씀드림`
- 인지: `딸이 언제 오는지 세 번 물으시며 걱정된다고 하셨습니다. 점심 후에 오신다고 말씀드렸습니다.`
- 행동: 빈칸. 입력에 없는 안도감이나 이후 행동은 추가하지 않는다.

- 입력: 사건 `복도를 천천히 걸음. 창가의 꽃을 보고 예쁘다고 말씀하심`, 반응 `웃으심`, 조치 `걸으실 때 팔을 잡아드림`
- 인지: `창가의 꽃을 보시고 예쁘다고 말씀하시며 웃으셨습니다.`
- 행동: `복도를 천천히 걸으셨습니다. 걸으실 때 팔을 잡아드렸습니다.`
- 따뜻한 분위기를 내려고 입력에 없는 미소·감사·안도감이나 작성자의 감상을 보태지 않는다.

## 핵심 흐름

1. 대상자를 선택한다.
2. 날짜와 관찰 메모를 입력한다.
3. 일일 인지·행동 기록 초안을 생성한다.
4. 결과를 검토하고 수정하거나 복사한다.
5. 한 주의 일일 기록이 충분하면 주간 종합 기록을 생성한다.

## 로그인과 이용 권한

모든 Google 계정으로 로그인할 수 있다. 인증된 새 사용자는 기본 workspace를 자동으로
받아 자신의 대상자와 기록을 바로 만들고 AI로 초안을 생성할 수 있다. 1인 공간과
향후 기관 공간은 같은 모델을 사용한다. 자료의 공간 소속, 작성자, 구성원 관계와
작업별 권한은 서로 구분한다.

공유는 향후 기관(workspace) 단위로 확장한다. 현재 대상자 화면에는 개별 어르신의
이메일 공유·권한 부여·해제 UI를 제공하지 않는다. 기관 구성원 관리·초대·역할 설정은
후속 작업이며, 현재 구성원 추가만으로 기존 자료가 공개되지는 않는다.
기존에 저장된 명시 권한의 읽기·편집 검사는 유지하고, 기관 공유로 전환할 때 자료 범위와
권한 전환 규칙을 별도로 정한다. UI 제거만으로 기존 자료나 권한을 변경하지 않는다.

## 날짜와 과거 기록 편집

현재 기록 날짜와 “오늘”은 한국 시간(`Asia/Seoul`)으로 고정한다. 향후 기관 위치와
시간대에 맞게 변경하는 옵션을 제공하며, 현재는 기관 설정 UI를 구현하지 않는다.
코드의 날짜 기준은 [아키텍처](./architecture.md#시간-기준)의 한곳에서 관리한다.

지난주를 포함한 과거 기록도 수정 권한이 있으면 편집할 수 있어야 한다. 작성자는
자기 기록의 수정 권한을 기본으로 부여받고, 다른 사용자도 부여된 권한에 따라
수정할 수 있다. 과거 날짜라는 이유로 수정을 막거나 작성자만 수정하도록 제한하지
않는다. 기준은 작업별 권한이며 작성자별 자료 격리를 요구하지 않는다.
작성자는 대상자 읽기 권한을 유지하는 동안 자기 기록의 수정·삭제 권한을 갖는다.
공유가 완전히 철회되면 작성자도 그 대상자의 기록에 접근할 수 없다. 편집 공유를 받은
다른 사용자도 과거 기록을 편집할 수 있다. 기존 미배정 자료는 별도 승인된 공간·권한
배정 전까지 노출하지 않는다.

## MVP 범위

포함:

- 대상자 등록과 선택
- 날짜별 관찰 메모 입력
- 일일 인지·행동 기록 생성
- 생성 결과 수정, 복사, 삭제
- 일일 기록을 이용한 주간 기록 생성
- 로컬 Ollama 연동

제외:

- 진단, 위험도 판정, 치료 또는 투약 권고
- 케어포 계정 비밀번호 저장
- 케어포 화면 무인 자동 입력
- 보호자에게 보고서 자동 발송
- 다기관 결제와 복잡한 권한 체계

현재 구현 여부와 다음 작업은 [로드맵](./roadmap.md)에서 관리한다.

## UX 원칙

- 모바일을 우선하고 주요 버튼의 터치 영역과 글자를 충분히 크게 만든다.
- 사용자가 작업 맥락을 잃지 않도록 불필요한 페이지 이동을 줄인다.
- 상태와 결과를 명확한 텍스트로 설명하고 장식보다 기록 작업에 집중한다.
- 색상은 `src/app/globals.css`에 정의된 의미 기반 토큰을 사용한다.
- 접근성이 필요한 복합 UI는 Base UI (headless primitive)를 사용한다.

## 개인정보 기준

대상자의 인지·행동 기록은 민감한 돌봄 정보로 취급한다.

- AI 요청과 로그에 불필요한 식별정보를 넣지 않는다.
- `.env`, 데이터베이스, 백업을 Git에 커밋하지 않는다.
- 운영 접속은 인증된 HTTPS 프록시 또는 사설망으로 제한한다.
- Ollama와 SQLite를 공용 인터넷에 직접 노출하지 않는다.
- 대상자와 기록의 조회·작성·수정·삭제는 Google 로그인과 별도의 이용 권한 검사를 거친다. workspace 소속과 명시 공유 범위를 벗어난 자료는 조회·수정·AI 입력에 포함하지 않는다. 운영별 설정은 [운영 가이드](./operations.md)를 따른다.
